Based on the provided `CONTEXT.md`, here is a read-only risk review of the **Smart Campus** repository across correctness, maintainability, security, dependencies, and agent operations.

---

## 1. Correctness & Edge-Case Risks

* **Timezone and DST parsing variance in `checkAvailability` (`src/availability.js`)**
* **Risk:** `new Date(request.start)` and `new Date(b.start)` parse naive ISO strings (`"2026-10-28T09:00:00"`, missing a `Z` or offset) in the host machine's local timezone. If a test runner or browser operates in a timezone experiencing a Daylight Saving Time (DST) transition on the target day, `(end - start) / 60000` can drift by $\pm 60$ minutes, breaking the 120-minute `MAX_DURATION_MINUTES` boundary.


* **Evidence:** `NOW_ISO = '2026-10-28T09:00:00'` and `at = (hhmm) => `${DAY}T${hhmm}:00`` in `src/rooms.js`, consumed via `new Date(...)` in `src/availability.js`.




* **Missing defensive type/null guards on `room` and `bookings` (`src/availability.js`)**
* **Risk:** Calling `checkAvailability` directly with `room = null`/`undefined` or `bookings = null` throws an unhandled `TypeError` (`Cannot read properties of undefined (reading 'blocked')` or `bookings is not iterable`) instead of gracefully returning `{ status: 'Unavailable', reason: ... }`.


* **Evidence:** `if (room.blocked)` and `for (const b of bookings)` execute without nullish checks.




* **Cross-midnight or arbitrary date inputs in `checkAvailability` (`src/availability.js`)**
* **Risk:** While the UI restricts inputs to `<input type="time">` prefixed with `DAY`, the pure function `checkAvailability` accepts arbitrary ISO date-time strings (`request.start`, `request.end`) without verifying that the booking occurs on the same calendar day as `now` or within campus operating hours.


* **Evidence:** `src/availability.js` checks `start < now` and `(end - start) / 60000 <= 120`, so a request for a future year or `23:30` to `00:30` the next day passes if no existing booking overlaps.




* **Uncaught `undefined` equipment IDs in `renderRoomCard` (`src/app.js`)**
* **Risk:** If a catalog room contains an equipment key not registered in `EQUIPMENT`, `EQUIPMENT[id]` evaluates to `undefined`, rendering blank commas in the UI (`Capacity 20 · Projector, `), whereas `emptyStateText` in `src/messages.js` explicitly falls back via `EQUIPMENT[id] ?? id`.


* **Evidence:** Line 64 of `src/app.js` uses `room.equipment.map((id) => EQUIPMENT[id]).join(', ')`.




* **Stale result remains visible when time inputs change (`src/app.js`)**
* **Risk:** Changing `#start` or `#end` after submitting the form does not clear or refresh `#result` until the user clicks "Check availability" again, leaving a previous slot's result displayed alongside new input values.


* **Evidence:** Event listeners in `src/app.js` attach to `attendees` (`input`), `equipment` (`change`), `roomList` (`change`), and `form` (`submit`), with no `input`/`change` handler on `el.start` or `el.end`.





---

## 2. Security & DOM Hygiene Risks

* **`innerHTML` interpolation violates `AGENTS.md` coding conventions (`src/app.js`)**
* **Risk:** `AGENTS.md` mandates: *"Build DOM text with `textContent`. Never put data into `innerHTML`."* However, `src/app.js` constructs DOM nodes via template-literal `innerHTML` in two places. Although `ROOMS` and `EQUIPMENT` are currently static and frozen, any future dynamic catalog data containing `<`, `>`, or `"` would introduce a DOM-based XSS vector.


* **Evidence:**
* `option.innerHTML = ` ${label}`;` (lines 24–25).


* `card.innerHTML = `<input type="radio" ... /> ${room.name} ...`;` (lines 65–69).






* **External third-party OpenGraph / Twitter image URLs in `index.html**`
* **Risk:** `index.html` references `[https://bolt.new/static/og_default.png](https://bolt.new/static/og_default.png)` in `og:image` and `twitter:image` meta tags, leaking referrer metadata to an external host (`bolt.new`) when links are unfurled and failing if that asset is removed.


* **Evidence:** Lines 8–10 of `index.html`.





---

## 3. Maintainability & Repository Hygiene Risks

* **Missing `.gitignore` and committed build artifacts (`dist/`)**
* **Risk:** The file tree shows no `.gitignore`, while hashed production bundle files (`dist/assets/index-CCqqJ5vM.js`, `dist/assets/index-CuTdS8qQ.css`, `dist/index.html`) are tracked in the repository. Every build changes hashed filenames, inflating diffs and risking merge conflicts or stale `dist/` artifacts if a developer forgets to rebuild before committing.


* **Evidence:** Section 2 file tree and Section 3 note (*"There is no .gitignore, no ESLint config and no tsconfig/jsconfig"*).




* **Missing `ACCEPTANCE.md` and `README.md` contents in review context**
* **Assumption / Risk:** Both files appear in the file tree, and `AGENTS.md` states *"`ACCEPTANCE.md` lists AC-1..AC-5. They must stay true,"* but their contents are omitted from `CONTEXT.md`. Any reviewer or agent relying solely on `CONTEXT.md` cannot verify whether `ACCEPTANCE.md` contains edge-case stipulations beyond the comments in `src/availability.js`.




* **No static analysis or type checking (`ESLint` / `checkJs`)**
* **Risk:** Without ESLint or JSDoc type checking (`tsconfig.json` with `checkJs: true`), violations of repository rules (such as `innerHTML` usage, `new Date()` calls inside rule modules, or JSDoc signature drift) are not caught automatically.

* **Risk:** `src/messages.js` imports `MAX_DURATION_MINUTES` from `./availability.js` and `EQUIPMENT` from `./rooms.js`. While acyclic today, any future import of `messages.js` inside `availability.js` or `rooms.js` would create a circular module dependency.

## 4. Dependency & Supply-Chain Risks

* **Critical & moderate vulnerabilities in devDependencies (`vitest` / `tinypool`)**
* **Risk:** `npm audit` reports 3 vulnerabilities (2 critical in `tinypool <= 2.1.1`, 1 moderate in `vitest` / `@vitest/mocker`). While `npm audit --omit=dev` shows 0 production runtime vulnerabilities (the app ships zero runtime dependencies), running test suites on untrusted code or shared CI runners exposes the build environment to the `tinypool` vulnerability.


* **Constraint conflict:** `AGENTS.md` forbids upgrading packages without human approval of the exact `package.json` / `package-lock.json` diff, and resolving `tinypool` requires a major upgrade from `vitest` `3.2.7` to `5.x` (breaking).




* **Major version lag across all devDependencies**
* **Risk:** `jsdom` (`25.0.1` vs `31.0.1`), `vite` (`6.4.5` vs `8.3.8`), and `vitest` (`3.2.7` vs `5.1.1`) are behind current major releases, increasing migration effort when security patches are eventually applied.

## 5. Agent Operations & Governance Risks

* **Manual `AGENTS.md` injection dependency**
* **Risk:** `AGENTS.md` notes that the file must be pasted manually when tooling does not load it automatically. If an agent starts a session without `AGENTS.md` in context, it has no visibility into hard constraints such as keeping `T01–T10` byte-identical, working off `main`, avoiding `new Date()`, or requiring human approval before editing `tests/availability.test.js`.




* **Prompt-injection surface via room data (`room.name`, `room.id`)**
* **Risk:** Although `ROOMS` is currently hardcoded and deep-frozen (`src/rooms.js`), if future tasks load external or user-supplied room catalogs, `room.name` is interpolated directly into `innerHTML` in `src/app.js` and echoed into `#result` (`${text} (${room.name})`), creating both an XSS vector and a downstream text-injection surface if outputs are consumed by automated agents.




* **Unenforced review gates (`AGENTS.md`)**
* **Risk:** Rules prohibiting direct commits to `main`, requiring byte-identical `T01–T10` tests, and gating edits to `AGENTS.md` or `tests/availability.test.js` rely entirely on agent compliance rather than Git hooks, `CODEOWNERS`, or CI checks.

// Smart Campus — booking / availability rules (AC1-AC5). Pure: no DOM, no data of its own.
// History: Practice #08 fixed BUG-A (strict < and > in the overlap test) and BUG-B (in-place sort).
// Assignment #04: INVALID_TIME guard added; the unnecessary sort was removed.

export const MAX_DURATION_MINUTES = 120;

/**
 * Checks whether a room can be booked for [start, end).
 * @param {{start: string, end: string}} request  ISO date-time strings
 * @param {{id: string, blocked: boolean}} room
 * @param {Array<{id: string, roomId: string, start: string, end: string}>} bookings
 * @param {Date} now  fixed "current time" (injected so tests are deterministic)
 * @returns {{status: 'Available'|'Unavailable', reason: string}}
 */
export function checkAvailability(request, room, bookings, now) {
  const start = new Date(request.start);
  const end = new Date(request.end);

  // AC1: missing or unreadable times are never Available
  // (before this guard every comparison with NaN was false and the function returned Available)
  if (!request.start || !request.end || Number.isNaN(start.getTime()) || Number.isNaN(end.getTime())) {
    return { status: 'Unavailable', reason: 'INVALID_TIME' };
  }

  // AC1: start must be before end, and not in the past
  if (start >= end) return { status: 'Unavailable', reason: 'START_NOT_BEFORE_END' };
  if (start < now) return { status: 'Unavailable', reason: 'IN_THE_PAST' };

  // AC2: maximum duration 120 minutes
  const minutes = (end - start) / 60000;
  if (minutes > MAX_DURATION_MINUTES) return { status: 'Unavailable', reason: 'TOO_LONG' };

  // AC3: blocked room
  if (room.blocked) return { status: 'Unavailable', reason: 'ROOM_BLOCKED' };

  // AC4: overlap check. The order of bookings does not matter (we stop at the first conflict),
  // so no sorting is needed; the bookings array is only read, never changed (AC5, former BUG-B).
  for (const b of bookings) {
    if (b.roomId !== room.id) continue;
    const bStart = new Date(b.start);
    const bEnd = new Date(b.end);
    // FIX BUG-A: strict < and > — "10:00-11:00" and "11:00-12:00" do NOT conflict
    if (start < bEnd && end > bStart) {
      return { status: 'Unavailable', reason: 'OVERLAP' };
    }
  }

  // AC5
  return { status: 'Available', reason: 'OK' };
}

// Smart Campus — room filtering rules (F1, F2). Pure functions: no DOM, input arrays are never changed.
// Blocked rooms are NOT hidden here: they stay visible with a "Blocked" label and the
// availability check always answers Unavailable for them (F3).

/** Parses the attendees field. Returns a whole number >= 1, or null when the text is not valid. */
export function parseAttendees(text) {
  const t = String(text ?? '').trim();
  if (!/^\d+$/.test(t)) return null;
  const n = Number(t);
  return n >= 1 ? n : null;
}

/** F1: capacity must be greater than or equal to the requested attendees. */
export function meetsCapacity(room, attendees) {
  return room.capacity >= attendees;
}

/** F2: the room must contain ALL required equipment items (no items required -> true). */
export function hasAllEquipment(room, required) {
  return required.every((item) => room.equipment.includes(item));
}

/**
 * Returns a NEW array with the rooms that satisfy every selected requirement.
 * An empty result is valid: the UI then shows the empty state (F4).
 * @param {Array} rooms
 * @param {{attendees: number, equipment?: string[]}} criteria
 */
export function filterRooms(rooms, { attendees, equipment = [] }) {
  return rooms.filter((room) => meetsCapacity(room, attendees) && hasAllEquipment(room, equipment));
}

// Smart Campus — room-list view model (Assignment #05, Task 03).
// Pure: turns the raw filter inputs into everything the room list needs to show.
// Before this module, app.js render() mixed these rules with DOM updates and they could only be tested through jsdom.
import { filterRooms, parseAttendees } from './filters.js';
import { emptyStateText, INVALID_ATTENDEES } from './messages.js';

/**
 * @param {Array} rooms  the catalog
 * @param {{attendeesText: string, equipment: string[], selectedId: string|null}} input
 * @returns {{attendees: number|null, matching: Array, selectedId: string|null,
 *            filterError: string, emptyText: string, countText: string}}
 */
export function buildRoomView(rooms, { attendeesText, equipment, selectedId }) {
  const attendees = parseAttendees(attendeesText);
  const matching = attendees === null ? [] : filterRooms(rooms, { attendees, equipment });

  // keep the current selection while it still matches, otherwise select the first match (or none)
  const keepSelection = matching.some((room) => room.id === selectedId);

  let emptyText = '';
  if (matching.length === 0) emptyText = attendees === null ? INVALID_ATTENDEES : emptyStateText(attendees, equipment);

  return {
    attendees,
    matching,
    selectedId: keepSelection ? selectedId : (matching[0]?.id ?? null),
    filterError: attendees === null ? INVALID_ATTENDEES : '',
    emptyText,
    countText: `${matching.length} of ${rooms.length} rooms match.`,
  };
}

// Smart Campus — UI presentation only. It reads the DOM, calls the pure rules and renders the answers.
// No booking rule or filter rule is written here; they live in availability.js and filters.js.
import { checkAvailability } from './availability.js';
import { buildRoomView } from './roomView.js';
import { EQUIPMENT, findRoom } from './rooms.js';
import { describeResult, formatTime } from './messages.js';

/**
 * Wires the page in `doc` to the given data. Exported so the UI can be tested with jsdom.
 * @param {Document} doc
 * @param {{rooms: Array, now: Date, nowIso: string, day: string}} data
 */
export function createApp(doc, { rooms, now, nowIso, day }) {
  const $ = (id) => doc.getElementById(id);
  const el = {
    attendees: $('attendees'), filterError: $('filter-error'), equipment: $('equipment-options'),
    roomCount: $('room-count'), roomList: $('room-list'), empty: $('empty-state'),
    selected: $('selected-room'), nowLabel: $('now-label'), bookings: $('booking-list'),
    form: $('check-form'), start: $('start'), end: $('end'), button: $('check-button'), result: $('result'),
  };
  let selectedId = null;

  el.nowLabel.textContent = `${day}, ${formatTime(nowIso)}`;
  for (const [id, label] of Object.entries(EQUIPMENT)) {
    const option = doc.createElement('label');
    option.className = 'chip';
    option.innerHTML = `<input type="checkbox" value="${id}" /> ${label}`;
    el.equipment.appendChild(option);
  }

  const requiredEquipment = () =>
    [...el.equipment.querySelectorAll('input:checked')].map((input) => input.value);

  function hideResult() {
    el.result.hidden = true;
    el.result.textContent = '';
  }

  function showResult() {
    const room = findRoom(rooms, selectedId);
    if (!room) return hideResult();
    const request = {
      start: el.start.value && `${day}T${el.start.value}:00`,
      end: el.end.value && `${day}T${el.end.value}:00`,
    };
    // F5: the check always uses the bookings of the room that is selected right now
    const { tone, text } = describeResult(checkAvailability(request, room, room.bookings, now));
    el.result.hidden = false;
    el.result.className = `result ${tone}`;
    el.result.textContent = `${text} (${room.name})`;
  }

  function renderRoomDetails() {
    const room = findRoom(rooms, selectedId);
    el.selected.textContent = room ? `${room.name} (${room.id})` : 'none selected';
    el.bookings.replaceChildren(
      ...(room ? room.bookings : []).map((b) => {
        const li = doc.createElement('li');
        li.textContent = `${formatTime(b.start)}–${formatTime(b.end)} (${b.id})`;
        return li;
      }),
    );
    if (room && room.bookings.length === 0) {
      const li = doc.createElement('li');
      li.textContent = 'No bookings today.';
      el.bookings.appendChild(li);
    }
    el.button.disabled = !room;
  }

  function renderRoomCard(room) {
    const card = doc.createElement('label');
    card.className = `room${room.blocked ? ' blocked' : ''}`;
    const equipment = room.equipment.map((id) => EQUIPMENT[id]).join(', ');
    card.innerHTML = `
      <input type="radio" name="room" value="${room.id}" ${room.id === selectedId ? 'checked' : ''} />
      <span class="room-name">${room.name} <small>${room.id}</small></span>
      <span class="room-meta">Capacity ${room.capacity} · ${equipment}</span>
      ${room.blocked ? '<span class="badge">Blocked — cannot be booked</span>' : ''}`;
    return card;
  }

  /** Recomputes the matching rooms and keeps the selection consistent with them. Rules: roomView.js */
  function render() {
    const previous = selectedId;
    const view = buildRoomView(rooms, {
      attendeesText: el.attendees.value, equipment: requiredEquipment(), selectedId,
    });
    selectedId = view.selectedId;

    el.filterError.hidden = view.filterError === '';
    el.filterError.textContent = view.filterError;
    el.roomList.replaceChildren(...view.matching.map(renderRoomCard));
    el.roomCount.textContent = view.countText;
    // F4: clear empty state
    el.empty.hidden = view.emptyText === '';
    el.empty.textContent = view.emptyText;

    renderRoomDetails();
    // F5: if the selected room changed, an old answer would belong to another room -> refresh it
    if (selectedId !== previous && !el.result.hidden) showResult();
  }

  el.attendees.addEventListener('input', render);
  el.equipment.addEventListener('change', render);
  el.roomList.addEventListener('change', (event) => {
    if (event.target.name !== 'room') return;
    selectedId = event.target.value;
    renderRoomDetails();
    if (!el.result.hidden) showResult(); // F5
  });
  el.form.addEventListener('submit', (event) => {
    event.preventDefault();
    showResult();
  });

  render();
  return { getSelectedId: () => selectedId };
}

// @vitest-environment jsdom
// Task 03 evidence: baseline app.js vs refactored app.js on the same inputs; compares visible DOM state.
import { it, expect } from 'vitest';
import { readFileSync } from 'node:fs';
import { URL as NodeURL } from 'node:url';
import * as oldApp from './old/src/app.js';
import * as newApp from './new/src/app.js';
import { ROOMS, NOW, NOW_ISO, DAY } from './new/src/rooms.js';

const html = readFileSync(new NodeURL('./index.html', import.meta.url), 'utf8');
const ATT = ['', '0', '1', '7', '8', '9', '12', '20', '21', '30', '31', '80', '81', '500', '2.5', 'abc', '-3'];
const EQ = ['projector', 'whiteboard', 'computers', 'video', 'microphone'];

function mount(mod) {
  const doc = new DOMParser().parseFromString(html, 'text/html');
  mod.createApp(doc, { rooms: ROOMS, now: NOW, nowIso: NOW_ISO, day: DAY });
  return doc;
}
function act(doc, att, mask, room) {
  const g = (id) => doc.getElementById(id);
  doc.querySelectorAll('#equipment-options input').forEach((b, i) => { b.checked = !!(mask & (1 << i)); });
  g('attendees').value = att;
  g('attendees').dispatchEvent(new window.Event('input', { bubbles: true }));
  const r = doc.querySelector(`input[name="room"][value="${room}"]`);
  if (r) { r.checked = true; r.dispatchEvent(new window.Event('change', { bubbles: true })); }
  g('start').value = '11:00'; g('end').value = '12:00';
  g('check-form').dispatchEvent(new window.Event('submit', { bubbles: true, cancelable: true }));
}
const snap = (doc) => ['filter-error', 'room-count', 'room-list', 'empty-state', 'selected-room', 'booking-list', 'result']
  .map((id) => { const e = doc.getElementById(id); return `${id}|${e.hidden}|${e.innerHTML}`; }).join('\n');

it('baseline and refactored UI produce identical DOM for every input sequence', () => {
  let cases = 0, diffs = 0;
  const o = mount(oldApp), n = mount(newApp);
  for (const att of ATT) for (let mask = 0; mask < 32; mask++) for (const room of ['R-101', 'R-303', 'R-404', 'none']) {
    act(o, att, mask, room); act(n, att, mask, room); cases++;
    if (snap(o) !== snap(n)) diffs++;
  }
  console.log(`EQUIVALENCE cases=${cases} differences=${diffs}`);
  expect(diffs).toBe(0);
});
